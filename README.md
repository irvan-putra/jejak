# Bidirectional Requirements Traceability - Gemini Proposal

This repository preserves a proposal generated by Google Gemini about automating bidirectional traceability between requirements (BRS/SRS), architecture, and code. The text is attributed to Gemini and recorded here in November 2026.

## What this is

- An idea-stage AI proposal, kept as a reference document. Nothing here is implemented or validated.
- The concept: maintain a Requirements Traceability Matrix (RTM) automatically, in both directions. Forward traceability links requirements to the architecture and code that implement them; backward traceability links code back to the business requirement or user story that motivated it.
- The proposal suggests three enabling techniques: semantic chunking and embeddings for mapping natural-language requirements to code, AST/code-graph parsing for structural links, and an agentic CI/CD step that flags broken mappings on pull requests.

## Runnable prototype

`rtm.py` demonstrates the two traceability directions on an embedded example
project (or your own files): it parses requirements from Markdown and code
units with the `ast` module, links them by TF-IDF cosine similarity, and
reports possible coverage gaps (forward) and possible orphan code (backward).
All links are inferred heuristics, not verified coverage - see
`framing-and-limitations.md`.

    python3 rtm.py                     # text report
    python3 rtm.py --viz rtm_heatmap.png   # similarity heatmap (needs matplotlib)
    python3 rtm.py --reqs REQS.md --src src/   # your own project

See `TESTING.md` for verified commands, dependencies, and known limits.

## Suggested next experiment (15 Nov 2026)

Suggestion, not a commitment or a result: make the next milestone evidence,
not more features. Try `rtm.py` on one small real Python repo with 5-10
requirements. Write down the expected requirement-to-code links yourself
before running it, then grade its suggestions: useful, wrong, or missed.
The script already accepts requirements and a source directory
(`--reqs REQS.md --src src/`), so that tests something real without a
bigger platform build.

If the links help, a PR-check integration becomes worth considering. If
they are mostly noise, improve the matching or park it cheaply. Either
result is useful, and could become an honest portfolio write-up if shared.
